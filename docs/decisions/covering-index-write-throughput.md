## 0. 카드 A가 이미 답한 것 · 안 답한 것

2026-08-22 카드 A(로컬, i3-6100 2물리코어)가 커버링 인덱스의 쓰기 대가를 **논리 페이지 수정
카운터**로 확정했다:

- **A÷B = 1.245**(`Innodb_buffer_pool_write_requests`) — 독립 카운터 `Innodb_log_write_requests`도
  1.242로 0.3% 안에서 일치
- 행당으로 풀면 **+1.046 페이지 수정/행** — "세컨더리 인덱스 엔트리 하나 = 리프 페이지 수정
  1회"라는 산수가 그대로 맞아떨어짐(통계적 추정이 아니라 산수 확인)
- 팔 간 **겹침 0**(A 최소 106,254 > B 최대 85,556) — 이 카운터로는 잡음이 거의 없다

그런데 이 판 자신이 §3에 명시적으로 적어뒀다: **"`ms`(시간)는 3.8배 잡음이라 못 쓴다 — 쓰기
**처리량**은 여전히 미측정, 조용한 박스가 필요"**. 같은 팔 B가 판마다 71.8초~272.3초로
3.8배 벌어지는데 카운터는 0.33% 안에 붙는다 — "행당 논리 작업이 24.4% 늘어난다"는 사실과
"그게 실제 처리량(RPS)·지연(p99)에 얼마나 반영되는가"는 다른 질문이고, 후자는 카드 A가
못 답했다.

**이 문서는 그 처리량 질문 하나만 다룬다.** 카드 A의 카운터 결과를 재확인하거나 바꾸는 것이
아니다.

## 1. 왜 조용한 박스가 필요한가

카드 A는 i3-6100(물리 2코어)에서 돌았다. [[project_loadtest_env_constraint]]가 이 박스를
"절대 RPS·천장 무의미, 메커니즘·상대·델타만 신뢰"로 규정하는데, 카드 A의 `ms` 잡음(3.8배)이
정확히 그 증거다 — 같은 조건·같은 팔인데 시간만 재현이 안 된다.

원인은 카드 A README §2가 이미 짚었다: 이 박스는 "여전히 잡음투성이"다 — 다른 프로세스(관측
스택·OS 스케줄링 등)와의 동거가 시간 측정에 노이즈를 얹는다. 논리 카운터(`bp_write_req` 등)는
그 동거의 영향을 거의 안 받아서 카드 A가 답을 냈지만, `ms`는 원천적으로 그 동거를 그대로
반영한다. **처리량을 재려면 그 동거 자체를 없애야 한다** — 즉 조용한 박스가 필요조건이다.

## 2. 무대 — Q2(從 R12)의 조용한 박스 선례를 재사용

파티션 재측정(從 R12, 2026-08-24)이 정확히 같은 문제를 겪었다 — 로컬 판이 "팔 안 산포가 팔
효과보다 커서 못 가른다"로 끝났고, EC2 조용한 박스 + 잡음 노브(`WARM_DROP`·`SETTLE_SEC`)로
산포를 **9.4배 → 1.9배**까지 접은 뒤에야 팔이 보였다.

이 실험도 같은 처방을 쓸 수 있다:

| Q2가 쓴 것 | 이 실험에 적용 |
|---|---|
| 단독 EC2 인스턴스(부하기 동거 없음) — "조용한 박스"의 정의 자체 | 그대로 — MySQL 하나만 뜬 박스, rig도 같은 박스에서 돎(원격 부하기 불필요, 단일 라이터 판이라) |
| 라틴 방격 블록화(순서 효과 분리) | 그대로 — [[feedback_measure_design_needs_repeats]] |
| 무대를 블록마다 새로 세움(교락 제거) | 그대로 — 카드 A와 같은 이유(§4, "먼저 쓴 쪽이 느리다" 같은 교락 방지) |
| 페이지/행 게이트(무효 판 걸러내기) | 그대로 — 카드 A §5-5가 "넣다 죽은 판을 유효 판으로 센" 결함을 이미 한 번 겪었다 |

🔴 EC2 인스턴스 타입은 Q2 결과 문서에 명시돼 있지 않다(확인 필요) — 착수 시 그때 쓴 것과
같은 타입을 재사용할지, 새로 정할지는 미결정(§5).

## 3. 팔 구성 — 카드 A와 동일, 지표만 교체

새 가설이 아니다. 카드 A의 A(커버링 인덱스 있음)/B(없음) 팔을 그대로 쓰고, 판정 지표만
바꾼다:

| | 카드 A | 이 실험 |
|---|---|---|
| 팔 A | `idx_report_cover` 있음 | 동일 |
| 팔 B | `idx_report_cover` 없음 | 동일 |
| 페이로드 | 판당 20,000행(800문 × 25행), 문당 커밋, `flush_log_at_trx_commit=1`·`sync_binlog=1` | 동일(재현성을 위해 바꾸지 않는다) |
| 판정 지표 | `bp_write_req`·`log_write_req`(논리 카운터) | **RPS·p50·p99(ms) — 이 실험의 목적 그 자체** |
| 판 수 | 8판(1판 버림) | Q2 선례가 13블록까지 필요했다 — 카드 A의 8판이 조용한 박스에서도 충분할지는 미확정(§5) |

**change buffer는 안 켜진다**는 것도 카드 A 후속(2026-08-22)이 이미 세 페이로드 모양(집중·
분산-새id·분산-기존id)에서 확인했다 — 이 실험은 그 결론을 재검증할 필요가 없다. 즉 카드 A가
관측한 "+24.4%는 나중에 청구되는 비용이 아니라 그 자리에서 다 낸다"는 전제를 그대로 깔고,
그 비용이 시간으로 얼마인지만 잰다.

## 4. 채택 여부와의 관계

카드 A README §7이 이미 명시했다 — **"채택 여부는 열려 있다. 이 판은 대가의 크기만 준다.
채택은 사용자 결정"**. 이 실험도 마찬가지다: 처리량 숫자가 나와도 "그러니 커버링 인덱스를
빼야 한다/유지해야 한다"를 이 문서가 대신 결정하지 않는다. 순수하게 **측정 갭**(논리 대가는
아는데 시간 대가는 모른다)을 메우는 것이 목적이다.
