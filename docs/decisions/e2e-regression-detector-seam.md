## 0. 무엇을 정하는가

E1 통주행(회원가입 → 세션 시작 → 프레임 → rep → Spring 콜백 → `pose_data` 적재 → 리포트)을
**저장소 안의 것만으로 다시 돌릴 수 있게** 만든다. 지금은 못 한다.

정할 것은 하나다 — **어느 경계에서 MediaPipe 를 갈아끼우고, 그 대가로 무엇을 못 보게 되는가.**

`e1_walkthrough.py` 는 **2026-08-16 에 실제로 통과했다**(`edb91cf`). 그런데 그 통과를 재현할 수 없다.

| `ai-server/scripts/demo_videos/demo_squat.mp4` | 얼굴만 잡힌 찍다 만 테이크. 하체 가시성 **0.24** 로 `VISIBILITY_FLOOR=0.55` 에 전량 걸린다 |
| 합성 인체 `figure()` | 아래 §2 |

### 🔴 값싼 길 하나가 2026-08-21 에 반증됐다

「`figure()` 의 궤적을 standing 까지 닿게 그리면 된다」를 검토했고, **안 된다**는 것을 실측했다
([#266 코멘트](https://github.com/Shadowfit/init/issues/266)).

```
squat   검출   3D(현행)   2D(z 제거)   판정(문턱 100/150)
 0.00     X       —          —         (콜드스타트 검출 실패)
 0.25     O     93.03     172.98       bottom
 0.50     O     83.82     159.33       bottom
 0.75     O     83.67     146.35       bottom
 1.00     O    112.69     174.74       -
```

- **ㄱ.** 3D 각도가 어떤 자세에서도 **113° 를 못 넘는다.** `STANDING_THRESHOLD=150` 이 도달 불가다
  → 궤적을 어떻게 그려도 rep 은 0 이다
- **ㄴ.** 🔴 **z 를 빼도 안 된다.** 가장 깊게 앉은 `squat=1.0` 이 2D **174.74°**(거의 편 다리)로
  나오고 `squat=0.75` 가 146.35° 다 — **깊이와 단조가 아니다.** MediaPipe 가 이 만화 그림에서
  무릎을 따라가지 못한다

ㄴ 이 중요한 이유: **[#217](https://github.com/Shadowfit/init/issues/217)(3D→2D)을 고쳐도 이 길은
안 열린다.** 즉 「합성 이미지 + 실제 MediaPipe」 조합은 죽었다.

⚠️ 미검증: 자세당 1프레임이고 검출기 하나를 순차로 썼다(트래킹 잔상). **비단조성**에는 그 영향이
있을 수 있으나, ㄱ 은 검출된 4자세 전부에서 같은 방향이다.

## 2. 그래서 남은 것은 «어느 경계를 가짜로 두나»

파이프라인을 경계로 끊어 보면 이렇다.

```
[영상/카메라] → [MediaPipe 검출] → [랜드마크] → [각도·rep 판정] → [gRPC 콜백]
      ①              ②                 ③              ④              ⑤
                                              → [Spring] → [MySQL] → [리포트]
                                                   ⑥          ⑦         ⑧
```

- **옵션 A**(영상 커밋)는 ①부터 전부 실물이다. **검출 품질까지 증명하는 유일한 길**이다
- **옵션 B**(이 문서)는 **③에서 끊는다** — ①②를 가짜로 두고 ③~⑧을 실물로 돌린다

🔴 **그래서 B 는 #196 이 실제로 겪은 실패를 못 잡는다.** #196 의 원인 ①이 「하체가 프레임 밖이라
가시성 0.24」였는데, 그건 정확히 ②의 문제다. **B 로 만든 회귀가 초록이어도 「검출이 된다」는
말은 못 한다.** 이 한계는 회귀 스크립트 머리와 결과 문서에 같이 박아야 한다.

B 가 답하는 질문은 좁다 — **「랜드마크가 들어오면 rep→적재→리포트가 끝까지 도는가」.**
그게 #196 이 «배관은 통과했는데 내용이 비었다» 로 물었던 절반이다.

## 3. 이음매 후보 넷

### ㄱ. 프로덕션에 env 게이트 fake detector

`lease_detector()`(`mediapipe_detector.py:311`)가 설정값을 보고 가짜 검출기를 돌려준다.

- **장점**: 컨테이너로 띄운 **진짜 서버**가 그대로 돈다. `docker compose up` 뒤 E1 드라이버를
  그대로 쓴다 — 지금 드라이버를 거의 안 고친다
- **단점**: **프로덕션 코드에 시험용 갈래가 생긴다.** 이 저장소는 그런 것에 보수적이다
  (`V5` 가 `DEFAULT 0` 을 뗀 이유, `#230` 이 토큰 동일을 **기동 거부**로 막은 방식)
- **완화**: 켜졌으면 기동 로그에 🔴 로 찍고, 응답에도 표시를 남긴다. 다만 **완화는 규율이지
  구조가 아니다** — 운영 `.env` 에 그 키가 들어가는 사고를 막는 것은 사람이다

### ㄴ. in-process 하네스가 이음매를 patch (프로덕션 무변경) ⭐

테스트 하네스가 FastAPI 앱을 **같은 프로세스에서** 띄우고 `lease_detector` 만 갈아끼운다.
Spring·MySQL 은 `docker compose` 로 진짜를 쓴다.

- **선례가 이미 있다**: `ai-server/tests/test_auth_middleware.py:12,24,46` 이 `TestClient` 로 앱을
  띄운다. 새 기계장치가 아니다
- 이 세션에서 쓴 `tests/test_pose_response_contract.py` 가 `mock.patch.object(pose_endpoint,
  "lease_detector", ...)` 로 **바로 그 이음매를 이미 갈아끼우고 있다** — 동작이 확인된 방법이다
- **장점**: 프로덕션 코드 **변경 0.** 갈아끼움이 시험 코드 안에만 있다
- **단점**: **컨테이너로 띄운 서버가 아니다.** uvicorn 기동·미들웨어 순서·스레드풀 거동 등
  «배포 형태» 에서만 나는 문제는 못 잡는다. HTTP 경계는 `TestClient` 가 태우지만 네트워크는 아니다
- **단점 2**: 하네스가 ai-server 의존성을 **로컬에** 요구한다(`.venv`). 지금도 테스트가 그렇게 돈다

### ㄷ. 시험 전용 HTTP 엔드포인트 (랜드마크를 직접 POST)

- **장점**: 컨테이너 진짜 서버 + 네트워크 경계까지 실물
- **단점**: ㄱ 보다 **더 큰** 프로덕션 변경이다. 인증·라우팅·스키마가 다 붙는 새 공개 표면이고,
  그 표면은 «판정에 아무 랜드마크나 밀어넣을 수 있는 구멍» 이다. 게이트가 새면 피해가 ㄱ 보다 크다

### ㄹ. 옵션 A (실제 영상) — 대조군으로 남긴다

B 를 하더라도 **A 를 지우면 안 된다.** B 는 ②를 영영 안 본다. 언젠가 영상 하나를 찍어 넣으면
그때 ①②가 덮이고, 그 둘은 **서로를 대체하지 않는다.**

### 비교

| | 실물로 도는 구간 | 프로덕션 변경 | 검출(②)을 보나 | 배포 형태를 보나 |
|---|---|---|---|---|
| ㄱ env 게이트 | ③~⑧ + 컨테이너·네트워크 | 🔴 있음 | ❌ | ✅ |
| **ㄴ in-process** | ③~⑧ | ✅ **없음** | ❌ | ❌ |
| ㄷ 시험 엔드포인트 | ③~⑧ + 컨테이너·네트워크 | 🔴 더 큼 | ❌ | ✅ |
| ㄹ 실제 영상 | ①~⑧ 전부 | ✅ 없음 | ✅ | ✅ |

**추천은 ㄴ 이다.** 「프로덕션 코드를 안 건드린다」가 이 저장소의 기존 규율과 맞고, 이음매를
갈아끼우는 방법이 **이미 코드에 있어 검증됐다.** ㄱ 이 더 사주는 것(컨테이너·네트워크)은
E1 이 원래 묻던 것(«rep→적재→리포트가 도는가»)이 아니다.

## 4. 합성 랜드마크를 어디서 얻나

`ai-server/tests/test_squat_analyzer.py` 의 `_frame(knee_angle, torso_tilt)` 가 이미 필요한 것을
만든다 — 33개 랜드마크를 무릎 각도로부터 해석적으로 생성하고, **z 를 0 으로 둔다.**

z=0 이면 현행 3D 각도 계산이 2D 와 같아지므로 문턱 100/150 이 그대로 성립한다. 실제로 이 저장소의
rep 카운팅 테스트들이 그 방식으로 rep 을 만들어 세고 있다 — 즉 **「랜드마크로 rep 을 만들 수
있다」는 이미 증명돼 있다.**

🔴 **여기서 [#303](https://github.com/Shadowfit/init/issues/303) 과 같은 함정이 선다.** `_frame` 은
`tests/` 안에 있어서 회귀 하네스가 어디에 놓이냐에 따라 «복사» 하고 싶어진다. 복사하면
`synthetic_body.py` 가 겪은 드리프트 문제가 재현되고, 그걸 막으려 또 게이트를 만들게 된다.
**하네스를 `tests/` 안에 두면 이 문제가 아예 안 생긴다** — §6 의 결정과 얽힌다.

## 5. 이 회귀가 판정하는 것 / 못 하는 것

**판정한다**
- 랜드마크 → 각도 → rep 경계 판정이 실제로 rep 을 만드는가
- rep 완성 시 Spring 콜백(`SavePoseDataBatch`)이 가는가
- `pose_data` 에 행이 실제로 앉는가 (멱등 키 `uk_pose_event` 포함)
- 세션 종료 → 리포트 선계산이 도는가, 리포트 필드가 0 이 아닌가
- 🆕 «판정 0» 진단이 **안 울리는가** (`#267` 에서 넣은 `needs_intake_warning`)

**판정 못 한다 — 이걸 문서와 스크립트 머리에 박는다**
- **검출 품질**(②). #196 의 진짜 원인이 여기였다
- 카메라·인코딩·프레임 속도 등 클라 쪽 현실
- (ㄴ 을 고르면) 컨테이너·네트워크·uvicorn 기동

## 6. 어디서 도나 — CI 는 오늘 못 받는다

실측: `.github/workflows/` 에 잡이 7개인데 **`docker compose` 로 스택을 띄우는 테스트 잡은 없다**
(`cd-backend.yml`·`split-modules.yml` 이 compose 를 언급하지만 배포·모듈 분리용이다).
`ai-server-test.yml` 은 `unittest discover` 만 돌린다.

즉 이 회귀는 **MySQL + Spring 이 필요하므로 오늘 CI 에 그대로 못 올린다.** 선택지:

- **(가) 로컬/수동 rig 으로 둔다** — `loadtest/` 나 `ai-server/scripts/` 에 놓고 사람이 돌린다.
  지금 E1 드라이버와 같은 지위다
- **(나) `tests/` 에 두되 스택이 없으면 `skipUnless` 로 건너뛴다** — CI 에서는 조용히 넘어가고
  로컬에서만 돈다. 🔴 **「건너뛴 것」이 「통과」로 보이는 함정**이 있다. 이 저장소가 반복해서
  경계한 형태다(#267 이 바로 그 부류였다). 건너뜀을 요약에 **소리 나게** 남겨야 한다
- **(다) CI 에 통합 잡을 새로 만든다** — MySQL 서비스 컨테이너 + Spring 빌드. 리드타임이 있고
  이 문서의 범위를 넘는다

## 8. 미검증

- ~~ㄴ 하네스가 Spring 까지 닿는지 — compose 포트 매핑을 확인 안 했다~~ → ✅ **경로는 열려 있다
  (2026-08-21 확인).** `docker-compose.yml:57` 이 Spring gRPC 를 `"6565:6565"` 로 호스트에 열고,
  AI 쪽 기본값은 `config.py:54` `BACKEND_GRPC_ADDRESS = "shadowfit-backend:6565"` 다. 하네스는
  이 값을 `localhost:6565` 로 덮으면 된다.
  ⚠️ 다만 **연결을 실제로 맺어보지는 않았다** — 확인한 것은 포트가 열려 있다는 것까지다
- 합성 랜드마크로 만든 rep 이 **sync_rate 를 0 이 아니게** 내는지 안 봤다. 정답지(`V4` 시드)와의
  DTW 거리에 딸린 값이고, [#192](https://github.com/Shadowfit/init/issues/192) 가 「정답지 0행이면
  rep 이 살아도 sync_rate 가 0」을 적어뒀다. **회귀의 판정선을 «rep > 0» 으로 둘지
  «sync_rate > 0» 까지 둘지가 이 확인에 딸린다**
- ㄱ 을 골랐을 때 「운영 `.env` 에 시험 키가 들어가는 사고」의 실제 확률은 모른다. 위 서술은
  논증이다
