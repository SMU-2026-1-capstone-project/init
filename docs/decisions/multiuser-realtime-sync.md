## 1. 기능 정의

여러 사용자가 **서로의 운동 상태를 실시간으로 보며 동기화**하는 기능. 브레인스토밍 원문 기준 두 형태:
- 파트너십: "오늘 파트너가 하체 운동을 완료했습니다 → 나도 이어서 운동하기" 식의 상호 진행 공유
- 그룹/대전: 여러 사용자가 같은 시간에 함께 운동하며 서로의 rep·자세 안정성 점수를 실시간으로 봄

이 중 **"파트너 완료 알림"은 이미 별도 결론이 남**(비실시간, 앱을 안 켜놔도 와야 하므로 Web Push/FCM 영역 — 스트리밍과 무관). 이 문서가 다루는 것은 **동시에 접속해 있는 상태에서의 실시간 동기화**(그룹/대전)로 좁힌다.

## 2. 필요한 기술 구조

```
사용자 A(WebSocket) ──┐
사용자 B(WebSocket) ──┼──> Spring(WebSocket Gateway, 여러 인스턴스) ──> Redis Pub/Sub(인스턴스 간 중계)
사용자 C(WebSocket) ──┘
```

- **양방향 필수**: 그룹 참여자 각자가 보내기도 받기도 해야 함 → WebSocket (gRPC-Web은 브라우저에서 bidi-streaming 자체를 지원 안 해 후보에서 제외됨)
- **N:N 브로드캐스트 조율**: 참여자 각자의 WebSocket 연결이 서로 다른 Spring 인스턴스에 흩어질 수 있음 → "누가 누구에게 브로드캐스트해야 하는가"를 Redis Pub/Sub(또는 Kafka) 같은 별도 계층이 중계해야 함
- **연결-사용자 매핑**: 어느 인스턴스가 어느 사용자의 연결을 들고 있는지 추적하는 presence 레지스트리 필요 — [`ai-sticky-routing.md`](./ai-sticky-routing.md)가 AI 쪽에서 이미 겪은 "세션이 어느 프로세스에 있나" 문제와 같은 종류이지만, 그쪽은 1세션-1프로세스 고정이라 더 단순했고 여기는 N명이 서로 얽혀 있어 더 복잡함

|---|---|---|
| 관계 형태 | 1:1 | N:N |
| 방향 | 단방향(서버→클라이언트) | 양방향 |

| 추정 공수(Claude 병행) | ≈17~19h | 이 문서 범위보다 큼, 별도 추정 필요 — pub/sub 계층·재연결 로직만으로 트레이너 안 전체 분량에 준하는 새 작업이 추가됨 |
| 혼자 감당 가능성 | 가능 | 리스크 큼 |

## 4. 포지셔닝과의 정합성

이 프로젝트는 "한 기능(스쿼트 분석 파이프라인)을 DB·인프라 레벨까지 깊게 판다"는 방향으로 이미 포지셔닝돼 있다([[project_db_portfolio_direction]]). 다중사용자 동기화는:
- DB 깊이 서사와 접점이 거의 없음(WebSocket 게이트웨이·pub/sub은 DB 쿼리·인덱스·트랜잭션과 무관한 별도 축)
- "좁고 깊게"가 아니라 "새 서브시스템을 넓게 추가"하는 방향이라 지금까지의 차별화 전략과 반대 방향

또한 실시간 소셜/멀티플레이어 기능 자체는 다른 포트폴리오에서도 흔히 시도되는 소재라 ([[project_portfolio_benchmark]]의 "채울 키워드" 쪽에 가까움), 잘 만들어도 차별화 효과가 기대만큼 크지 않을 수 있음.

## 5. 기회비용

`docs/tasks/24-semester2-plan.md`의 BE-06(Goal)·BE-07(패턴분석)·BE-08(추천)·BE-09(세트/운동확장)이 **아직 코드 자체가 없는 상태**로 이미 2학기 계획에 들어 있다(2026-08-30 확인, `Goal`/`Pattern`/`Recommend` 관련 파일·커밋 0건). 이 넷은:
- 이미 Spring 백엔드 작업으로 설계돼 있고

다중사용자 동기화를 넣으면 **이 넷과 정면으로 시간을 다투게 된다** — "남는 시간에 끼워 넣기"가 아니라 실제 트레이드오프.

## 6. 결론 (추천, 미확정)

**채택 비추천.** 이유:
1. 난이도·리스크가 이 브레인스토밍에서 나온 후보 중 가장 큼(N:N pub/sub, 혼자 감당)
2. DB 깊이라는 기존 포지셔닝과 거리가 멀고, 흔한 소재라 차별화 효과도 불확실
3. 이미 계획에 있고 아직 착수 안 된 BE-06~09와 정면으로 우선순위가 충돌

**대안**: 실시간성을 포폴 소재로 쓰고 싶다면 [`trainer-live-monitoring.md`](./trainer-live-monitoring.md)(실시간 트레이너 모니터링, SSE, 1:1)이 리스크·공수·포지셔닝 정합성 모두에서 더 나은 선택.
