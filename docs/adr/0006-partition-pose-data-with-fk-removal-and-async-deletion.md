# ADR-0006: pose_data를 파티셔닝하기 위해 FK를 제거하고, 회원 탈퇴 삭제는 이벤트 즉시 비동기로 대체한다

작성일: 2026-07-20
상태: Accepted
근거 문서: [`../decisions/pose-data-partition-fk-tradeoff.md`](../decisions/pose-data-partition-fk-tradeoff.md)

## Context

`pose_data`는 세션마다 계속 쌓이는 테이블이라 월별 Range 파티셔닝을 실측·검증해뒀다 — TTL 만료 시 `DROP PARTITION`이 동기 `DELETE`보다 약 625배 빠르다(로컬 실측, 8.3M행 기준 동기 삭제는 18.6분). 그런데 이걸 실스키마에 반영하려 하자 MySQL/InnoDB가 **FK가 걸린 테이블의 파티셔닝을 지원하지 않는다**(ERROR 1506)는 원천 제약에 막혔다. `pose_data.session_id → exercise_sessions(id) ON DELETE CASCADE`를 제거해야 파티셔닝이 가능한데, 이 CASCADE가 실제로 회원 탈퇴 시(`MemberService.deleteMember`) `users → exercise_sessions → pose_data`로 이어지는 정리 체인을 자동으로 수행하고 있었다. FK를 없애면 이 자동 정리가 사라지고 탈퇴 후에도 `pose_data`가 고아 행으로 남는다.

## Decision

**파티셔닝을 진행한다(FK 제거)**, 참조무결성은 **회원 탈퇴 시점에 이벤트를 즉시 트리거하는 비동기 처리**로 대체한다. 회원 탈퇴 API는 대량 삭제를 기다리지 않고 즉시 응답하되, 탈퇴 처리 시점에 곧바로(정기 배치 주기를 기다리지 않고) 백그라운드 정리 작업을 트리거한다. 개별 세션 삭제(`DELETE /sessions/{id}`, 소규모 고정 삭제량)는 이와 별도로 **동기 삭제**로 처리한다 — 삭제 트리거를 규모에 따라 다르게 다룬다.

## Consequences

- 얻는 것: TTL 만료 처리가 `DROP PARTITION`으로 사실상 무료가 되어, 데이터가 쌓일수록 커지는 `DELETE` 기반 만료의 운영 부담(락 시간 포함)을 장기적으로 제거한다. 회원 탈퇴 API 응답이 대량 삭제에 막히지 않는다.
- 감수하는 것: 참조무결성을 DB(FK CASCADE)가 아니라 애플리케이션이 책임지게 됐다 — 정합성 유지가 코드 경로(이벤트 트리거)의 책임으로 이동한다. 개인정보보호법 제21조("개인정보가 불필요해지면 지체 없이 파기")를 검토한 결과, 정기 배치만으로는 "지체 없이" 요건을 충족 못 할 소지가 있어 **이벤트 즉시 트리거**가 설계 제약으로 들어갔다. `pose_data`의 PK가 복합키(`id`, `created_at`)로 바뀐다.
- 다음에 영향받는 결정: 비동기 실행 메커니즘을 Spring `@Async`(단일 인스턴스 한정)로 할지 별도 큐/워커로 할지는 이 결정 시점엔 미확정으로 남았다(규모상 `@Async`가 적정해 보인다는 판단만 있었음). `exercise_sessions` 자체를 즉시 삭제로 둘지 소프트 삭제로 바꿀지도 별도로 열려 있었다.

## Alternatives considered

- A1(파티셔닝 보류, FK 유지) — 구현 비용·리스크가 0이지만, 데이터가 계속 쌓이는 테이블이라 시간이 지날수록 `DELETE` 기반 만료의 운영 부담이 누적돼 장기적으로 더 큰 비용이 된다.
- B1(동기 명시적 삭제) — 실측으로 증명된 "대량 DELETE 느림"(분 단위) 문제와 정면 충돌해 회원 탈퇴 API 응답 지연 위험이 크다.
- B2 원안(정기 배치로만 정리, 즉시 트리거 없음) — 법적 "지체 없이" 요건과 충돌 소지가 있어 그대로는 채택하지 않고, 이벤트 즉시 트리거로 변형(B5)해서 채택했다.
- B3(파티션 자연 만료에만 위임) — 탈퇴 후 최대 TTL 기간만큼 개인정보가 잔존하게 되어 법 위반 소지가 명확해 배제했다.
- B4(B1+B2 혼합, 세션 수 임계치로 동기/비동기 분기) — 분기 로직의 복잡도 대비 이득이 이벤트 즉시 트리거(B5) 단일 경로보다 낮다고 판단해 기각했다.
