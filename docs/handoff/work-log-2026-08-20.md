## 1. E2 — 수치에 조건 달기 (커밋 5개)

종료 조건 E2 는 「한 장짜리의 모든 수치가 조건과 근거 링크를 갖는다」이다.
같은 조건 문장을 수십 곳에 복붙하면 다음 변경 때 또 어긋나므로, **수치마다 조건 카드를
하나 세우고 인용처가 그것을 가리키게** 했다.

| 앵커 | 어디에 | 카드가 막는 오독 |

| `#index-9000x` | 〃 | 「인덱스를 **추가해서**」가 아니다 — 대조로 만든 값 |

### 지금까지 좁힌 것 (실측)

| 조합 | 결과 |
|---|---|
| main 전체 스위트 | ✅ 통과 (9m48s) |

| 프로브 + `OutboxPublisherFailureInjectionTest`(새 것) | 🔴 3회 실패 / ✅ 1회 통과 → **플래키** |
| 위 조합에서 새 테스트의 **전용 DB 오버라이드 제거** | 🔴 실패 — **DB 격리가 원인이 아니다** |

### 원인 (부분 규명)

프로브가 성공한 판의 자기 진단 출력:

```
저장 완주    : true
워밍업 행    : 1
pose_data 행 : 1   ← 포기당한 배치의 것
```

**10프레임 배치가 다운샘플(window=5) 후 1~2행만 남는다.** 판정이 `> 0` 이라
**여유가 사실상 1행**이다. 같은 JVM 에 스프링 컨텍스트가 하나 늘어 무거워지면
그 여유가 사라진다. 다운샘플 창 기본값은 양쪽 다 5로 **같다**(원인 아님).

### 한 조치 / 안 한 조치

- ✅ `dc3cf7c` — 새 테스트에서 **gRPC 서버를 껐다**(`grpc.server.port=-1`). 이 테스트는
  gRPC 를 안 쓰는데 서버가 같이 떴다. 확률은 줄었지만 **전체 스위트에서는 여전히 재현된다**
- ❌ **근본 원인은 그쪽 테스트의 여유가 1행이라는 것**이고 그건 안 고쳤다.
  프로브를 남의 테스트로 보고 손대지 않았다

### 다음 사람이 할 일 (제안, 미확정)

1. `GrpcServerDeadlineProbeTest` 의 `batchOf(10)` 을 **키워서 여유를 만든다**(예: 50프레임

2. 또는 그 테스트에서 다운샘플을 끈다(`pose-data.downsample-window=1`)
3. 또는 플래키로 인정하고 격리 실행으로 뺀다 — 권하지 않는다(회귀를 못 잡는다)
