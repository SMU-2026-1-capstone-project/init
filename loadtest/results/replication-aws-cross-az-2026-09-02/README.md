절대량 자체가 줄어 lag 도 같이 줄어든다. ⚠️ **이 라운드도 그 인과를 직접 검증하지 않았다** —
같은 미검증이 두 라운드에 걸쳐 반복된다.

## 3. Q2 — 반동기가 무는 값 (본 질문)

### 3-1. 다세션 본판 4 — 팔 평균

| | 팔 A (비동기) | 팔 B (반동기) | 대가 |
|---|---:|---:|---|
| 처리량 | **1,897.4** tx/s | **1,571.7** tx/s | **−17.2%** |
| 커밋 p50 | 7,463µs | 9,184µs | **+23.1%** |
| 커밋 p95 | 12,018µs | 14,192µs | **+18.1%** |
| 커밋 p99 | 19,399µs | 21,650µs | +11.6% |

판별값은 팔별 평균(A: 1893.8·1901.0 / B: 1564.4·1579.0 — REPS=2 라 08-22 의 3판 중앙값
대신 2판 평균을 썼다. 산포: A 0.27%·B 0.65%, 둘 다 작다).

**반동기가 실제로 돌았다**: 팔 B 에서 `yes_tx` 가 판당 **64,572~65,089** 증가, `no_tx=0` —
강등 없이 두 판 모두 진짜 반동기(`wait_point=AFTER_SYNC`, `gates.tsv` G2 OK).

### 3-2. 같은 AZ ↔ 다른 AZ — 나란히

| | 같은 AZ (08-22) | 다른 AZ (이 라운드) | 배수 |
|---|---:|---:|---:|
| 처리량 대가 | −5.9% | **−17.2%** | **2.9배** |
| 커밋 p50 대가 | +6.1% | **+23.1%** | **3.8배** |
| 커밋 p95 대가 | +13.0% | +18.1% | 1.4배 |
| 커밋 p99 대가 | +9.5% | +11.6% | 1.2배 |

🔴 **설계 §9-1 ②가 예견한 "자릿수 단위" 는 반증됐다** — 자릿수(10배 이상)는 안 벌어졌다.
**대신 확인된 것은 "여전히 한 자릿수 % 대이지만 방향이 뚜렷하게, 최대 약 3~4배 커진다" 다.**
그리고 **커진 정도가 평균(p50)에서 더 크고 꼬리(p99)에서는 오히려 작다** — 08-22 라운드가
"대가가 평균보다 꼬리에 크다"고 적었던 것과 반대 패턴이다. 이건 §1-1 의 왕복 분포와
같은 결로 읽을 수 있다 — cross-AZ 는 **p50 자체가 밀려 올라간** 것(1.3배)이지 **꼬리만
굵어진 것**(3.6배는 왕복 쪽 얘기)이 아니라서, 커밋 p50 이 왕복 p50 상승을 그대로 반영하고
p99 는 이미 같은 AZ 에서도 굵었던 꼬리(직렬화 등 다른 요인)에 묻힌다는 추정이다.
⚠️ **이것도 미검증 추론이다** — 원인 규명이 아니라 관측된 패턴을 적어둔다.

## 4. 정직하게 비어 있는 것

- 🔴 **H3(핫세션) 대조가 이번엔 없다** — 설계 §0-4 결정으로 이번 라운드는 다세션만 쟀다.
  「cross-AZ + 핫세션」이 동시에 걸리면 대가가 얼마나 더 커지는지는 **다음 라운드의 몫**이다
- 🔴 **REPS=2(4판)라 08-22의 REPS=3(6판)보다 산포 신뢰도가 낮다.** 그래도 판별값 간
  산포(A 0.27%·B 0.65%)는 08-22(A 0.6%·B 0.2%)와 같은 자릿수라 방향 판정에는 충분하다고 본다
- **Q1 의 "반동기 쪽 지연이 더 작다" 인과는 두 라운드 연속 미검증이다** — §2. 소스를 인위로
  같은 만큼 늦춘 비동기 대조판이 있어야 갈린다
- **§3-2 의 "p50 이 더 크게, p99 이 덜 크게 벌어지는" 설명은 추정이다** — 왕복 분포와의
  상관을 별도로 검증하지 않았다
- **판마다 리플리카를 다시 세우지 않았다** — `rows_before` 가 판을 거듭하며 커진다(25.8M →
  48.4M). 08-22 와 같은 설계상의 한계
- **합성 부하다** — 페이로드가 단일 템플릿 복제라 값 분포가 균일하다
  ([[project_synthetic_data_distribution_limit]])
- ⚠️ **실행 경위 자체가 불완전하다** — 위 경고 참고. 이 라운드를 누가·어떤 조건에서 트리거
  했는지 로그가 없다. 재현 명령 자체는 설계 §0-4 에 있고 이 산출물과 정합하지만, "그 명령이
  실제로 그대로 실행됐다"는 산출물(`conditions.txt`·`gates.tsv`·`D0_preflight.txt`)로부터의
  **역추정**이지 실행 로그로 확인한 사실이 아니다
- **재기동 실패 1건이 이 발견 과정에서 나왔다** — 같은 실험을 모르고 다시 띄우려던 시도가
  `repl_preflight` FAIL 직후 두 인스턴스가 통째로 종료되는 것을 만났다. 원인은 `run_all.sh` 의
  `FINAL_OK` 판정이 업로드 성공만 보고 phase 성공은 안 보는 로직 결함으로 규명됐다
  ([#641](https://github.com/Shadowfit/init/issues/641)). 그 과정에서 P4 절차 문서에 없던
  AL2023 root SSH 차단도 걸렸다([#642](https://github.com/Shadowfit/init/issues/642))
