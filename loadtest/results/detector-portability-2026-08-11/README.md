## 0. 한 줄 요약

**순차 호출이면 `PoseDetector` 는 스레드를 옮겨 다녀도 상태가 100% 보존된다 → ㄴ 안이 살았다.**

| 팔 | 구성 | 의미 | 검출률 | 세션이 거친 스레드 |
|---|---|---|---|---|
| **A** | 세션 전용 스레드 + 그 스레드의 검출기 | ㄷ 안 = 기준선 | **100.0%** | [1,1,1,1] |
| **B** | 회전 스레드 + **세션 전용 검출기** | **ㄴ 안 ← 급소** | **100.0%** | [4,4,4,4] |
| **C** | 회전 스레드 + 스레드 로컬 검출기 | 현행 = 대조군 | **25.0%** | [4,4,4,4] |

- **B − A = +0.0%p** → 「옮겨도 된다」
- **B − C = +75.0%p** → 검출기 소유만 바꿔도 25% → 100%

## 1. 왜 이 설계여야 했나

**동시성을 완전히 뺐다.** 섞으면 「옮겨서 깨진 것」과 「겹쳐서 깨진 것」이 안 갈린다.
순차로만 돌리면 락도 경합도 없고 **변수는 「스레드가 바뀌는가」 하나**만 남는다.

그리고 **B 와 C 는 스레드 배정 패턴이 동일하다**(둘 다 `(i+k) % 4` 회전).
검출기의 **소유**만 다르다 — 그래야 75%p 차이를 「소유 탓」으로 귀속할 수 있다.

## 2. 검산 (출력에 상시 포함)

이 rig 는 앞선 두 rig 가 조용히 틀린 뒤에 만들어져서, 스스로를 검산한다:

| 검산 | 기대 | 실제 |
|---|---|---|
| 전제 확인(사람이 단독 100%) | 4/4 | ✅ 4/4 |
| A(기준선) | 96% 근처 이상 | ✅ 100.0% |
| 세션이 거친 스레드 | A 는 1, B·C 는 2 이상 | ✅ [1,1,1,1] / [4,4,4,4] |

## 3. 무엇이 결정되나

- 🔴 **`session-detector-ownership.md §3-2` 의 미검증 전제가 해소됐다.**
  ㄷ 를 권하던 근거 3개 중 **1번(「ㄴ 은 미검증 전제 위에 선다」)이 사라진다.**
- 남은 ㄴ 의 부담은 **락 하나**(§3-1 — 클라 백프레셔가 없어 같은 세션 프레임이 겹칠 수 있다).
- 반대로 ㄷ 의 부담은 **동시 실행 수를 직접 제한해야 한다**(§3-3)는 것이고, 이건 새 컴포넌트다.

## 4. ⚠️ 한계

1. **합성 인체다.** #164 캐비엇 ③ 은 여전히 열려 있다.
2. **순차 전용 결과다.** 「동시 호출도 안전하다」는 **전혀 말하지 않는다** — 오히려 현행 주석대로
   동시 호출은 위험하다고 봐야 하고, 그래서 ㄴ 을 고르면 **락이 필수**다.
3. 판별 반복이 없다. 다만 100.0% / 100.0% / 25.0% 은 경계값이 아니라 **자릿수 차이**라
   반복이 결론을 바꿀 여지가 작다.
4. `close()` 시점·메모리(M2)는 안 쟀다.
