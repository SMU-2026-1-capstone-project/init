## 0. 한 줄

**두 박스는 같은 AMI·같은 커밋·동시 launch인데 calib `infer` 축이 12.9% 갈렸다.**
그런데 그 차이는 실측 처리량과 **안 맞고, 방향까지 반대**다. 대신 calib `cpu` 축(파이썬 루프

독립된 축에서 다시 맞아떨어진 셈이다.

🔴 **이 판은 「우리 문제냐 박스 문제냐」에 절반만 답한다** — n=2(박스 2대)뿐이고, 설계가
권장한 K=3은 계정 **32 vCPU 쿼터**에 막혀 못 했다(3번째 `run-instances`가 `VcpuLimitExceeded`로
즉시 거부됨 — 인스턴스는 안 만들어졌고 낭비는 없다).

## 3. 판정선 (설계 §4 그대로 적용)

### ㄱ — 보정값이 박스마다 다른가 (기준: 라운드 내 산포 ~0.3~0.4%)

| 축 | 박스 간 차이 | 판정 |
|---|--:|---|
| `infer` | 12.9% | 🟢 **산포를 훨씬 넘는다 — 박스 개체차 확정** |
| `cpu` | 0.6% | 🔴 산포 안 — 유의한 차이 아님 |

### ㄴ — 그 차이가 처리량 차이를 설명하나 (처리량비 ÷ 보정비 ≈ 1?)

```
처리량비(A÷B)        = 0.983
보정비(infer, A÷B)   = 1.129   →  0.983 ÷ 1.129 = 0.871   🔴 13%p 벗어난다 — 게다가 부호가 반대
보정비(cpu, A÷B)     = 0.994   →  0.983 ÷ 0.994 = 0.989   🎯 1.1%p 벗어남 — 산포(0.3~0.4%)에 근접
```

- **`infer` 축은 방향까지 틀렸다** — Box A가 mediapipe 추론은 12.9% 더 빠른데, 실제 처리량은
  오히려 1.67% 낮다. 이 축으로는 처리량 차이를 «설명»할 수 없다.
- **`cpu` 축은 거의 완전히 설명한다** — 부호도 크기도(−0.6% ↔ −1.67%는 여전히 3배 차이지만,
  최소 **같은 방향**이고 ㄴ의 비율 자체는 1에 훨씬 가깝다.

### ㄷ — 효율(fps / AI vCPU)이 보정과 같이 움직이나

🔴 **미실행** — 인스턴스가 예정보다 빨리 종료돼(축 정리 우선) 판별 CPU 샘플러 원본
(`arms_boxA.json`/`arms_boxB.json`의 `cpu` 필드)을 못 건졌다. 대화 로그에 남은 것은 위 표의
rps·판 수뿐이다.

## 4. 읽기 — 왜 `cpu` 축이 맞고 `infer` 축이 틀렸나

[§8](../ceiling-cause-stage2-2026-08-24/README.md)의 답은 **천장이 GIL-바운드 순수 파이썬
구간**(요청당 ~1코어)이라는 것이었다 — mediapipe 추론 자체는 C++ 안에서 GIL을 놓고 ~8.5코어로
병렬 처리된다. 그렇다면:

- **처리량을 좌우하는 것은 파이썬 루프의 원속도**(calib `cpu`)여야 하고,
- **mediapipe 단독 추론 속도**(calib `infer`)는 「GIL을 놓는 구간이 빠른가」를 잴 뿐이라
  전체 처리량과 직결될 이유가 약하다.

관측이 정확히 그 모양이다. **이건 §8을 반증하는 게 아니라, 독립된 축(박스 개체차)에서
같은 결론을 다시 만난 것**으로 읽는다.

## 5. 확정한 것과 안 한 것

- ✅ **`infer` 축은 박스마다 다르다**(12.9%, 산포의 30배 이상) — 박스 개체차는 실재한다
- ✅ **`infer` 축은 처리량 차이의 원인이 아니다** — 부호까지 반대
- 🟢 **`cpu` 축은 처리량 차이를 거의 설명한다** — 단, n=2라 «거의»의 신뢰구간은 없다
- 🔴 **판정선 ㄷ 미실행** — CPU 샘플러 원본을 못 건졌다
- 🔴 **n=2** — 설계 권장 K=3에 못 미친다(32 vCPU 쿼터). 분포로 말하려면 더 필요하다
- 🔴 **축 B(같은 박스 stop→start)는 미실행** — 호스트 이동 자체는 이 판이 안 건드렸다

## 6. 정직하게 비어 있는 것

- **K=3을 못 했다.** 계정 32 vCPU 쿼터가 `c7i.4xlarge`(16 vCPU) 2대에서 이미 찬다. K=3을
  하려면 쿼터 증설 요청이 먼저다
- **판별 CPU 샘플러(`cpu.ai`/`main`/`workers`) 원본을 잃었다** — 인스턴스를 결과 회수 전에
  종료했다(다른 세션이 같은 쿼터를 기다리고 있어 우선순위를 회수 완결보다 반납에 뒀다).
  다음 축 A 라운드는 **종료 전에 scp로 결과를 먼저 받는 순서를 지킬 것**
- **`infer` 축이 «왜» 갈리는지는 안 봤다** — 터보 클럭·이웃 소음 등 물리 호스트 상태는
  게스트에서 못 읽는다(설계 §6과 동일한 한계)
- **축 B(호스트 이동 단독)는 미실행** — ②(물리 호스트 차이)를 단독으로 흔드는 유일한 방법인데
  이 판은 A(박스 개체차)만 다뤘다
