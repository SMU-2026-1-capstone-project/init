## 4. 계측 ① — 스레드풀 상한은 «주된» 제약이 아니다

```
total_tokens   40          (anyio 기본, 0단계와 일치)
borrowed_max   40          ← 상한에 닿긴 한다
waiting_max   120          ← 160 − 40 과 정확히 같다
waiting 분포   0 이 3,824 / 4,006 표본  (95.5%)
borrowed 분포  40 이 197 표본 (약 5%)
```

🔑 **미묘하고, 그래서 분포를 남긴 것이 값을 했다.**
- **최대만 보면** 「120 이 대기한다」 — 상한이 병목처럼 보인다
- **분포를 보면** 표본의 **95.5% 가 대기 0** 이다 — 상시 제약이 아니다

⚠️ 0단계 프로브가 *「중앙값이 아니라 최대·분포를 남길 것」* 이라 적어둔 자리가 이것이다.
**최대만 남겼으면 ㄷ 으로 오독했을 것이다.**

## 5. 판정 — 설계 §6 표에 넣으면

| ① 스레드풀 대기 | ② `post_loop` | ③ loop lag | 결론 |
|---|---|---|---|
| **95.5% 가 0** | **19.94ms (22.7%)** | **p50 2ms · max 108ms** | 🟢 **ㄴ 단일 이벤트 루프** |

그리고 ①이 「대부분 0」이므로 **`wait` 19.39ms 의 대부분도 루프 디스패치 대기**다.

```
이벤트 루프에서 소모   wait 22.0% + post_loop 22.7% = 44.7%
실제 계산              infer 35.5% + decode 4.1% + post_app 1.1% = 40.7%
```

🔴 **요청 시간의 절반 가까이가 «한 이벤트 루프를 기다리는 것» 이다.**
프로세스를 쪼개면 루프도 갈라지므로, R10-a 의 **1.27~1.30배**가 여기서 설명된다.

⚠️ **`respond`(10.40ms)를 넣으면 56.5% 다.** 그 구간(응답 시작 → ASGI 이탈)도 루프에서 도는
전송이지만 **클라이언트가 읽는 속도도 탄다.** 그래서 **44.7% 를 보수적인 값으로, 56.5% 를
포함값으로** 둘 다 적는다 — 하나로 줄이지 않는다.

### 5-1. 🔑 `post_loop` 안의 «스케줄 대기» 는 이미 답이 나와 있다

`loop_lag` 이 재는 것이 「준비된 콜백이 얼마나 늦게 도는가」이고, 그것이 곧 스레드 반납 후
태스크가 다시 잡히기까지의 대기다.

```
post_loop  19.94 ms
loop_lag   p50 2.00 ms      ← 스케줄 대기
─────────────────────────
루프가 «하는 일»  ≈ 17.94 ms   (post_loop 의 90%)
```

🟢 **즉 `post_loop` 는 «기다림» 이 아니라 «일» 이다** — Pydantic 응답 검증과 JSON 인코딩이
후보다. 그것을 가르는 판이 [설계 §11](../../../docs/decisions/ai-process-ceiling-cause.md) 이다.
⚠️ **추정이다** — `loop_lag` 은 샘플러의 재개 지연이라 요청 태스크와 **같은 큐지만 같은 값은
아니다.**

## 6. 이 판이 확정한 것과 안 한 것

- ✅ **ㄴ(단일 이벤트 루프)이 주된 제약**이다 — 세 계측이 같은 방향을 가리킨다
- ✅ **ㄷ(스레드풀 상한)은 주된 제약이 아니다** — 다만 **완전히 아닌 것도 아니다**(최대 120 대기,
  borrowed 가 40 에 닿는 표본 5%). **2단계(상한 스윕)는 «없앨» 게 아니라 «순위가 내려간» 것**
- 🔴 **ㄱ(GIL)은 여전히 못 갈랐다.** 루프가 느린 이유가 「할 일이 많아서」인지 「GIL 을 못 잡아서」
  인지 이 판은 구분하지 않는다. 설계 §10 이 「ㄱ 을 직접 재는 수단이 없다」고 적어둔 대가다
- 🔴 **`post_loop` 안에서 무엇이 오래 걸리는지 모른다** — Pydantic 검증인지 JSON 인코딩인지
  스케줄 대기인지. 다음 판의 자리다

## 7. 정직하게 비어 있는 것

- 🔴 **처리량이 R10-a 3fps 판(319.2 rps)보다 12.9% 높다**(360.3). 계측을 **켰는데** 더 빠르다 —
  방향이 반대다. [라운드 간 비재현](../../../docs/decisions/round-to-round-nonreproducibility.md)([#498](https://github.com/Shadowfit/init/issues/498), +17.7%)의
  크기와 같아서 **그것으로 보이지만 확인 못 했다.** 🔴 **판 간 절대값 비교는 여전히 못 한다**
- **팔이 하나라 계측 ON/OFF 대조가 이 판에 없다.** R10-a 의 −1.27%(산포 이내)를 승계한다
- **부하기가 동거한다** — R10-a 실측 0.24 vCPU
- **`waiting_max 120` 이 언제 나는지 안 봤다** — 판 시작 직후 램프인지 정상 상태인지.
  분포만 있고 시계열이 없다
- **`loop_lag` max 108.5ms 가 어느 시점인지도 모른다** — 같은 이유
- **인터프리터 빌드가 기준과 다르다**(Red Hat GCC 11.5 ≠ Debian `python:3.12-slim`)
