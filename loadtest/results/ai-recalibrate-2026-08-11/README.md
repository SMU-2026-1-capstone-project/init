## 0. 한 줄 요약

**«DAU 1,000 의 피크 67세션에 5~10배 부족» 은 하드웨어 탓이었다. `c7i.2xlarge` 한 대(물리 4코어)면 65.5세션 — 거의 정확히 채운다.**

| | 2026-08-09 (i3-6100) | 2026-08-11 (Xeon 8488C) | 배수 |
|---|---|---|---|
| 프레임당 추론 | 103.4 ms | **17.6 ms** | **5.9x** |
| 포화 처리량 | 18.3 fps (스레드 4) | **196.6 fps** (스레드 8) | 10.7x |
| 동시 세션(클라 3fps) | 6 | **65.5** | 10.9x |
| **물리 코어당 세션** | 3.0 | **16.4** | **5.5x** |

→ **가정한 피크 67세션 = 물리 4.1코어.** 스케일아웃도 GPU 도 필요 없다.

### ⚠️ 프로덕션과 다른 점 두 가지 — 정직하게

1. **Python 3.11** 을 썼다. 프로젝트 Dockerfile 은 **3.12** 다. AL2023 저장소에 3.12 가 없었다.
   추론 비용은 C++ 확장에서 나오므로 minor 버전 차이가 값을 바꾸지 않는다고 보지만, **확인한 것은 아니다.**
2. **Docker 를 안 씌웠다.** 프로덕션은 컨테이너다. 컨테이너 오버헤드만큼 실제 값은 이보다 낮다.

> 그대로 갔으면 «다른 물건» 을 재고 그걸 인용했을 것이다. **핀을 맞추는 것이 측정의 일부다.**

## 2. 결과

### [A] 프레임당 추론 비용 — 트래킹 유지

| 구성 | n | 평균 | p50 | p95 | 최대 |
|---|---|---|---|---|---|
| 같은 사람 연속 | 160 | **17.6ms** | 17.6 | 18.5 | 18.9 |

검출 20/20, 무릎 visibility 0.848 — 2026-08-09 와 동일 조건임이 확인됐다.

### [B] 트래킹이 깨질 때 — 🔴 **하드웨어를 바꿔도 그대로다**

| | i3-6100 | Xeon 8488C |
|---|---|---|
| 각각 단독(전용 검출기) | 20/20 × 4 | **20/20 × 4** |
| 같은 검출기에 번갈아 | **11/20** | **11/20** |
| 시간 비용(B/A) | 1.19x | 1.26x |

**검출률 11/20 이 정확히 재현됐다.** [#164](https://github.com/Shadowfit/init/issues/164) 는 **CPU 성능과 무관한 구조 문제**이며,
장비를 올려도 사라지지 않는다는 것이 이번에 확인됐다.

⚠️ 이 45% 는 여전히 **최악의 경우**다(매 프레임 사람을 바꾼 합성 조건). 실제 스레드풀 배정 패턴에서의
빈도는 아직 안 쟀다 — #164 의 «다음 단계» 는 그대로 열려 있다.

### [C] 동시 스레드 포화 — 3판 + 버림판, 판마다 순서 반전

| 스레드 | 총 처리량(fps) | 판별 최소~최대 | 스레드당 평균ms | 1스레드 대비 |
|---|---|---|---|---|
| 1 | 43.9 | 43.3~46.4 | 18.6 | 1.00x |
| 2 | 78.6 | 77.0~78.8 | 21.0 | 1.79x |
| **4** (=물리코어) | 136.7 | 136.3~139.1 | 23.6 | **3.11x** |
| **8** (=논리코어) | **196.6** | 192.3~196.8 | 33.3 | **4.48x** ← 포화 |
| 16 | 194.6 | 193.6~198.9 | 65.3 | 4.43x (정체) |

- **포화점이 논리 코어 수(8)에 정확히 붙는다.** 16에서 처리량은 그대로고 스레드당 지연만 2배 — 전형적 포화.
- 물리 4코어에서 3.11x = 이상적(4.0) 대비 **78%**. i3 는 물리 2코어에서 1.79x 상당(63%)이었다 —
  **코어 확장 효율 자체도 이 CPU 가 낫다.**
- HT 가 물리 4 → 논리 8 에서 **+44%** 를 더 준다.
- 판 간 변동이 작다(최대 ±3%). 버림판 + 순서 반전이 실제로 드리프트를 잡았다.

### 유도

```
측정된 포화 196.6 fps ÷ 클라 3fps = 동시 65.5 세션  ⇒ 물리 코어당 16.39 세션
                     ÷ 클라 10fps = 동시 19.7 세션  ⇒ 물리 코어당  4.92 세션

물리  4코어 → 65.5     물리  8코어 → 131.1
물리 16코어 → 262.2    물리 32코어 → 524.4

가정 피크 67세션 → 물리 4.1코어
```

## 3. ⚠️ 이 값을 상한으로만 읽어야 하는 이유

1. **«코어를 100% 추론에 쓸 수 있다» 는 가정**이다. 실제로는 HTTP·base64 디코딩·GIL·같은 박스의 다른 컨테이너가 깎는다.
2. **#164 가 미해결이면 유효 처리량은 이보다 낮다.** 버려지는 프레임은 CPU 를 쓰고도 결과를 안 낸다.
3. **합성 인체 프레임**이다. 실제 카메라 프레임에서 트래킹이 얼마나 버티는지는 다를 수 있다.
4. 코어 선형 가정도 상한이다 — 메모리 대역·L3 경합은 코어가 늘수록 나빠진다.

**따라서 «물리 4코어면 67세션» 이 아니라 «상한이 65.5 이고 실제는 그 아래» 로 인용할 것.**
