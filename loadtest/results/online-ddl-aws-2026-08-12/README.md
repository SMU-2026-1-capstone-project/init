## 0. 판정

**팔 B(pt-osc)는 DDL 을 1.64배 오래 끄는 대신, 쓰기 정지를 3자릿수 배 줄인다.**
대가는 바이너리 로그다 — 팔 A 가 0MB 인 자리에서 441MB 를 쓴다.

| | 팔 A (차단 ALTER) | 팔 B (pt-osc) | 배수 |
|---|---|---|---|
| DDL 소요 | 68~70초 | 112~114초 | **B 가 1.64배 느림** |
| **최대 쓰기 정지** | **68,109~69,355 ms** | **30~364 ms** | **A 가 최소 187배 김** |
| writer 성공 시도 | 18회 | 553~558회 | B 가 30.8배 |
| binlog 증가 | **0 MB** | **441 MB** | — |
| 디스크 최대 | 2,359~2,377 MB | 2,348~2,352 MB | 사실상 동일 |
| p50 지연 | 4 ms | 4 ms | 동일 |

🔴 **핵심은 「A 의 최대 정지(≈69초) ≈ A 의 DDL 소요(≈69초)」다.** 팔 A 는 DDL 이 도는
내내 쓰기를 막는다 — 「느리지만 조금씩 통과」가 아니라 **전 구간 차단**이다. 1,000만 행에서
69초짜리 쓰기 공백이고, 이건 행 수에 따라 커진다.

반면 **디스크 최대치는 두 팔이 같다.** 「pt-osc 는 복사본을 만드니까 디스크를 더 쓴다」는
직관이 여기선 성립하지 않는다 — 팔 A 의 `ALGORITHM=COPY` 도 똑같이 전체 복사본을 만들기
때문이다. **pt-osc 의 대가는 디스크가 아니라 binlog 다.**

## 1. 전제 — INPLACE 는 서버가 거절했다

이 DDL(`PARTITION BY RANGE`)은 **`ALGORITHM=INPLACE` 가 불가능하다.** 소형 복제본에 직접
던져 확인했다:

```
ERROR 1845 (0A000): ALGORITHM=INPLACE is not supported for this operation.
                    Try ALGORITHM=COPY.
```

`LOCK` 절을 빼고 `INPLACE` 만 던져도 같은 1845 다 — 거절 사유는 **INPLACE 자체**이지
`LOCK=NONE` 이 아니다. 원문 [`ddl/probe_inplace_rejection.txt`](ddl/probe_inplace_rejection.txt).

> 즉 **「팔 A 대신 온라인 DDL 을 쓰면 되지 않나」는 이 DDL 에선 선택지가 아니다.**
> 선택지는 «69초 멈추거나(A)» «pt-osc 를 쓰거나(B)» 둘뿐이다. 이게 이 실험이 성립하는 이유다.

## 2. pt-osc 가 실제로 한 일

| 항목 | 관측 |
|---|---|
| 복사 대상 | `Copying approximately 9959994 rows` — ⚠️ **`COUNT(*)` 가 아니라 `EXPLAIN` 추정치다**(진행률 표시용. InnoDB 가 리프 페이지 표본에서 뽑는 값이라 ±수%). 실제 무대는 정확히 **10,000,000 행**(§3) |
| 청크 인덱스 | **`FORCE INDEX(PRIMARY)`** — 복합 PK `(id, created_at)` 를 그대로 씀 |
| 청크 경계 | `WHERE ((id > ?) OR (id = ? AND created_at >= ?))` — PK 두 칼럼 사전식 |
| 트리거 | `_ins` · `_upd` · `_del` 3개 생성 → 컷오버 후 삭제 |
| 컷오버 | `RENAME TABLE ... TO _old, _new TO ...` (원자적 스왑) |
| 복사 구간 | 16:15:11 → 16:17:02 (약 111초) |

**rig README 의 미검증 항목 「복합 PK 에서 pt-osc 가 어느 인덱스로 청크를 나누는지」가
이걸로 닫힌다** — 별도 인덱스를 만들지 않고 PK 를 그대로 쓴다. 근거
[`ddl/r2_B_ptosc.log`](ddl/r2_B_ptosc.log).

| 항목 | 값 |
|---|---|

| 커밋 | `6996e1cd9f7caae3f29456dbc7646e641e9920ec` (`work/2026-08-09`) |
| 실행 | `run_all.sh` 무인 · RUN_ID `ec2-20260812-160233` |
| 측정 시각 | 2026-08-12 16:02:34 ~ 16:31:28 UTC (ddl 단계 1,733초) |

**설계 — 버림 2판 + 본판 6판, 순서 `A B B A A B`.** 팔이 2개라 3라운드로는 라틴 방격이
불가능해 **위치 상쇄 배열**을 썼다(rig README §의 결정). 버림판을 팔마다 하나씩 둔 이유는,
한 팔만 버리면 다른 팔의 첫 판이 여전히 «첫 판» 이라 버림의 목적이 절반만 달성되기 때문이다.

원시 판별값 [`ddl/ddl.tsv`](ddl/ddl.tsv):

```
round	arm	ddl_s	attempts	errors	max_stall_ms	p50_ms	max_gap_ms	disk_peak_mb	binlog_mb
r1	A	70	18	0	69355	4	69558.0000	2359	0
r2	B	112	553	0	94	4	298.0000	2352	441
r3	B	113	553	0	364	4	569.0000	2352	441
r4	A	69	18	0	68961	4	69164.0000	2369	0
r5	A	68	18	0	68109	4	68312.0000	2377	0
r6	B	114	558	0	30	4	234.0000	2348	441
```

**errors 는 6판 전부 0 이다.** 팔 A 의 writer 는 죽은 게 아니라 **기다린 것**이다 —
정지를 «실패» 가 아니라 «지연» 으로 잡은 계측이라 `max_stall_ms` 가 의미를 갖는다.

판 간 재현성도 좋다: 같은 팔 안에서 `ddl_s` 가 ±1초, `binlog_mb` 가 완전 동일하다.

## 5. 인용 제한 · 미검증

- 🔴 **절대 소요 시간을 「운영에서 N분」으로 인용 금지.** 하드웨어 종속이다(설계 §5).
  **팔 간 상대 배수까지만** 쓴다. 「69초 정지」도 *1,000만 행 · m6i.xlarge · 이 스키마* 조건부다
- 🔴 **트리거 오버헤드를 환경에서 분리하지 못했다.** 팔 B 는 CPU 를 더 쓰는데 writer 를
  동시에 돌린다. 4 vCPU 라 로컬 2코어보다는 낫지만 **편향의 크기는 이 설계로 못 잰다**
- 🔴 **값 분포 한계.** 시딩이 단일 템플릿 복제라 카디널리티가 균일하다. 분포에 의존하는
  결론(옵티마이저 카디널리티·선택도)은 여기서 내지 않는다
- ⬜ **파티셔닝 «후» 의 성능은 안 쟀다.** 이 실험은 **DDL 을 어떻게 치를 것인가**만 본다.
  파티션 프루닝 효과는 별개 실험이다
- ⬜ **복제 환경에서의 pt-osc 는 안 쟀다.** binlog 441MB 가 복제 지연에 얼마를 더하는지는
  P4(복제 지연·반동기)의 몫이다 — 설계 문서부터 필요하다
- ⬜ **`--max-lag`·`--critical-load` 같은 pt-osc 안전장치는 기본값**이다. 튜닝 여지 미탐색

## 7. 회수 경로 — 결함 2건

이 결과를 회수하는 데 걸렸다. 다음 라운드에 같은 자리에서 또 막힌다:

1. **`MANIFEST.txt` 에 `S3_DEST` 가 없다.** 러너는 결과를 S3 에 올리면서 **어디에 올렸는지를
   남기지 않는다.** 버킷 이름이 repo 어디에도 없어(`iam/policy-s3-results.json` 은
   `__BUCKET__` 플레이스홀더) 사람에게 물어야 했다
2. **회수 주체에 읽기 권한이 없다.** `policy-s3-results.json` 은 **EC2 역할**에만 S3 권한을
   준다. CLI 사용자(`shadowfit-loadtest-temp`)는 `ListBucket`·`GetObject` 둘 다 거부됐다 —
   그런데 **업로드에 성공한 인스턴스는 스스로 꺼진다.** 무인 실행의 회수 경로가 안 닫힌다

> 곁가지: `~/.aws/credentials` 의 **`shadowfit-admin` 프로파일은 admin 이 아니다.**
> `default` 와 같은 `shadowfit-loadtest-temp` 키가 들어 있다(UserId 동일). 이름만 보고 쓰면
> 조용히 같은 권한으로 돈다.
