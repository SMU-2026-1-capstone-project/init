> **이미 같은 답을 냈다** — accept 큐 `Recv-Q` **132~135**, keep-alive **−0.9%**, 「큐는 증상이지

## 0. 한 줄

**연결 수립은 병목이 아니다** — 연결 하나가 **0.207ms** 이고, 재사용해도 처리량이 **+0.86%**
(판 간 산포 5.10% 안)다. **§9 의 −0.9% 를 16 vCPU 박스에서 재현했다.**

**§11-5 의 「밖에 130개」는 커널 accept 큐다** — 대기가 **128~137개**로 상시 쌓여 있고
keep-alive 판에서는 **0** 인데 **처리량은 같다.** 큐는 **비용이 아니라 자리**다.

### 0-1. 🟢 이 판이 §9 에 실제로 더한 것 넷

§9 는 **처리량 대조 하나**로 판정했다. 여기서 더해진 것:

| | §9 (2026-08-17) | 이 판 |
|---|---|---|
| **연결 하나의 값** | 안 쟀다(처리량에서 유도) | **0.207ms 직접 계측** |
| **라이브러리 대조군** | ❌ 없다 — `urllib`↔keep-alive 라 **「라이브러리 교체」와 「재사용」이 섞였다** | ✅ **N 팔**(새 연결·같은 라이브러리)로 갈랐다 — 교체분 **−0.24%** |
| **큐가 어디로 갔나** | 「처리 능력이 그대로라 총량이 안 변했다」로 **추론** | ✅ **계측** — `wait` 26→**220ms**, `total` 112→**581ms** |
| **연결 횟수 증거** | 없다 | ✅ N **24,050회** / K **160회** |

🔑 **두 번째 줄이 제일 크다.** §9 의 −0.9% 는 **두 변화가 겹친 값**이라 「재사용의 기여가 0」을
엄밀히는 못 말했다. 갈라보니 **교체 −0.24% · 재사용 +0.86%** 로 **둘 다 0** 이다.

## 2. 결과

| 팔 | 전송 | rps | 요청 | **연결 횟수** | `connect` p50 | `wait` | `total` |
|---|---|--:|--:|--:|--:|--:|--:|
| **U** | urllib | 266.4 | 22,700 | — (계측 밖) | — | 26.42 | 111.95 |
| **N** | new | 265.8 | 22,622 | **24,050** | **0.207 ms** | 26.38 | 113.33 |
| **K** | keepalive | 268.1 | 22,812 | **160** | 69.151 ms | **220.33** | **580.73** |

```
U → N  (라이브러리만)  −0.24%      ← 🟢 첫 확인 항목 통과. 교체가 조건을 안 바꿨다
N → K  (재사용만)      +0.86%      ← 🔴 재사용이 처리량을 안 바꾼다
U 팔 판 간 산포 5.10%              ← 셋 다 그 안이다
```

### 2-1. 🟢 연결 횟수가 팔을 증명한다

- **N: 24,050회** — 요청 22,622건보다 많다(버림 구간·재연결 포함). **요청마다 새 연결이 맞다**
- **K: 160회** — 세션 수와 정확히 같다. **재사용이 실제로 됐다**

⚠️ **U 는 연결 계측이 없다**(`urlopen` 이 노출을 안 한다). 그래서 가운데 `N` 을 뒀다 —
N 이 U 와 같으므로(−0.24%) **U 의 연결 비용도 N 과 같다고 읽는다.**

### 2-2. 🔑 연결 하나가 0.207ms 다

초당 ~265개를 열지만 **한 개당 0.2ms** 다. 판 전체(90초) 합이 22.5초인데 **160 스레드에 나뉘므로
스레드당 0.14초 = 판 시간의 0.16%** 다.

**연결 수립은 병목이 아니다.** 후보 하나가 지워졌다.

## 3. accept 큐가 「밖의 130개」다 (§9-1 재현)

listening 소켓의 `Recv-Q`(= accept 를 기다리는 연결)를 100ms 마다 걷었다 — 표본 **11,080개**:

```
0 인 표본        3,590 (32.4%)     ← K 판(12판 중 4판 = 33.3%)과 맞는다
128~137 덩어리   상시              ← U·N 판
최대             137
backlog 상한     2048              (여유는 충분하다)
```

**§11-5 가 리틀의 법칙으로 「ASGI 밖에 128~131개」라 했고, accept 큐가 「128~137개」다 — 같은 것이다.**

🔴 **그런데 이건 §9-1 이 이미 낸 관측이다** — 같은 문서가 2026-08-17 에 `Recv-Q` **132~135 지속**,
`ListenOverflows` **0**, backlog **2048** 을 적었고 리틀 검산까지 했다(`133 ÷ 237/s = 561ms`).
**나는 다른 박스·다른 부하에서 같은 값을 다시 봤을 뿐이다.**

🟢 **더해진 것은 대조다** — §9 는 한 조건, 여기는 **팔 셋 × 4판**이고 **K 팔에서 0** 이 같이
나왔다. 「U·N 이면 130, K 면 0」은 §9 에 없다.

### 3-1. 🔑 그게 «비용» 이 아니다 — §9-3 의 추론을 계측으로 바꿨다

K 팔에서 accept 큐는 **0** 인데 처리량은 **+0.86%** 로 같다. 대신 **`wait` 이 26 → 220ms,
`total` 이 112 → 581ms 로 폭발**했다.

**대기가 사라진 게 아니라 자리를 옮긴 것이다:**

```
U·N   연결이 커널 accept 큐에서 기다린다      → ASGI «밖»
K     연결이 이미 열려 있어 요청이 바로 들어와 → ASGI «안» 에서 기다린다(wait 220ms)
```

**닫힌 루프라 총량이 같다.** 160세션이 480 fps 를 내미는데 서버가 265 를 처리하면 **남는 것은
어딘가에서 기다려야 하고**, 그 «어딘가» 가 팔에 따라 바뀔 뿐이다.

🔑 **그래서 §11-5 의 「계측이 20% 만 본다」는 «계측의 결함» 이 아니었다** — 나머지 80% 는
**일이 아니라 큐**였고, 큐는 병목이 아니라 **병목의 결과**다.

🟢 **§9-3 이 「역방향 인과였다 — 앱이 천천히 가져가서 큐가 길다」로 이미 적었고, 이 판은 그
옮겨간 자리를 «숫자로» 보였다**(`wait` 26→220ms). §9 는 ASGI 안을 못 봤다 —
`frame_path` 구간이 그때는 없었다.

## 5. 이 판이 확정한 것과 안 한 것

- ✅ **연결 수립은 병목이 아니다**(0.207ms · 재사용해도 +0.86%)
- ✅ **「밖의 130개」는 커널 accept 큐다** — **§9-1 의 재현**이고 「U·N 130 ↔ K 0」 대조가 더해졌다
- ✅ **그것은 비용이 아니라 큐의 위치다** — **§9-3 의 추론을 계측으로 바꿨다**(`wait` 26→220ms)
- 🟢 **§9 의 −0.9% 에서 «라이브러리»와 «재사용»을 갈랐다** — 각각 −0.24% · +0.86%
- ✅ **「keep-alive 가 +38%」 반증** · **U↔N 이 같아** 라이브러리 교체가 조건을 안 바꿨다
- 🔴 **그래서 천장의 원인은 여전히 «서버가 265~360 rps 밖에 못 낸다» 이고, 그건 ㄱ(GIL) 아니면
  ㄹ 이다.** 이 판은 **후보를 지웠을 뿐 답을 안 냈다**

## 6. 정직하게 비어 있는 것

- 🔴 **이 박스의 절대값이 어제보다 낮다.** U 팔이 **266.4 rps** 인데 어제 같은 조건이 **354.5** 였다
  (**−25%**). [라운드 간 비재현](../../../docs/decisions/round-to-round-nonreproducibility.md)([#498](https://github.com/Shadowfit/init/issues/498)) 계열로 보이지만 **확인 못 했다.**
  🟢 **판정은 판 안의 대조로만 했으므로 이 차이에 안 걸린다**
- **accept 큐의 0 표본이 K 판의 것이라고 «시각으로» 대조하지 않았다** — 32.4% ↔ 4/12=33.3% 라는
  비율 일치로 읽었다
- **U 는 연결 계측이 없다** — N 과 같다는 것에서 유도했다(§2-1)
- **커널 accept 큐와 uvicorn accept 루프를 못 가른다** — 「밀린다」까지만 답한다
- **K 의 `connect` p50 69ms 는 판 시작 시 160 스레드가 동시에 연결한 값**이다. 정상 상태의
  연결 비용이 아니다
- 🔴 **rig 은 판마다 uvicorn 을 새로 띄운다**(`run_arms.py:415`) — 검출기 풀이 **매 판 차게
  시작**한다. §9-4 가 이 우회를 **−24%(348→260~270)** 로 실측했다. **팔에도 날짜에도 공통이라
  판정엔 안 얹히지만, 이 판의 절대값은 «차가운 풀» 눈금**이고 348·354 같은 값과 **직접 비교
  대상이 아니다**
- 🔴 **내가 §11-5 를 「새 질문」으로 적은 것이 문서 중복을 낳았다** — 같은 폴더의 §9 를 안 봤다.
  [#445](https://github.com/Shadowfit/init/issues/445) 계열인데 **이번엔 다른 세션이 아니라 나다**
- **합성 부하다** · **부하기가 동거한다**(R10-a 실측 0.24 vCPU)
