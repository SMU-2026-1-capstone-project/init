## 0. 한 줄

**"N=3이 답"은 SMT가 만든 숫자였다.** 물리 코어만 있는 박스(같은 `c7i.4xlarge`, SMT만 끔)에서는
**N=2에서 이미 box의 99%**를 쓴다 — N=3·4는 오차범위 안의 미세 개선뿐이다. 그런데 **원인(GIL,
단일 프로세스가 박스 전체를 못 씀)은 그대로 재현된다** — 바뀐 건 "몇 개가 최적인가"라는 처방의
크기이지, "왜 프로세스를 쪼개야 하는가"라는 원인이 아니다.

### 판정선 ㄱ — 인접 팔 차 vs 두 팔 산포 합 (원판과 같은 기준)

```
A→B (1→2)   +19.08%   산포합 1.07%   🟢 올랐다
B→C (2→3)    +1.92%   산포합 0.41%   🔴 사실상 천장 — box가 이미 99%에서 100%로 1%p 오르는 값
C→D (3→4)    +0.82%   산포합 0.39%   🔴 산포 안 — 여기가 진짜 천장
```

숫자로는 B→C가 판정선을 넘지만, `cpu.box`가 B에서 이미 **99%**라는 걸 같이 보면 다르게 읽힌다 —
**B(N=2)에서 이미 사실상 포화**고, C·D는 남은 1%p 여유를 쥐어짜는 것뿐이다. 원판(SMT 켬)의
"N=3, 98%"와 비교하면 **포화 지점이 한 단계 앞당겨졌다.**

## 3. 원판(SMT 켬) 대조

| | 원판 — SMT 켬 (16 vCPU = 8 물리코어) | 이번 — SMT 끔 (8 vCPU = 8 물리코어) |
|---|---|---|
| N=1 (팔 A) | 335.6 rps · AI CPU 9.60 · box 61%(9.80/16) | 279.9 rps · AI CPU 6.59 · box **84%**(6.71/8) |
| 포화 지점 | **N=3** (98%) | **N=2** (99%) — 사실상 N=1→2에서 이미 끝 |
| N=1→포화 rps 배수 | 335.6→451.2 = **1.34배** | 279.9→333.3(N=2) = **1.19배**, →342.4(N=4) = **1.22배** |

🔑 **핵심 발견 — 단일 프로세스가 "박스의 얼마를 쓰는가"가 SMT 유무로 크게 달라진다.**
SMT 켠 박스에서 프로세스 1개는 16개 하드웨어 스레드 중 9.60개(61%)를 물었는데, SMT 끈
박스(물리 코어만 8개)에서는 1개가 8개 중 6.59개(**84%**)를 문다. 즉 **하이퍼스레딩이 단일
mediapipe 프로세스에게 "추가로 쓸 수 있는 코어"를 거의 주지 못했다** — SMT를 꺼서 하드웨어
스레드 수가 반토막 나도, 남은 물리 코어의 **더 큰 비율**을 즉시 채워버린다. 이건 "GIL이 프로세스당
~1개 스레드로 직렬화하고, mediapipe C++ 쪽만 나머지를 병렬로 쓴다"는 원판의 원인 설명(§8,
`ceiling-cause-stage2-2026-08-24`)과 방향이 같다 — **다만 mediapipe C++ 쪽이 실제로 부릴 수 있는
"물리 코어 단위의" 병렬성은 원판이 「16 중 8.5」로 읽었던 것보다 작다**(대략 물리 코어 5.5~6개
안팎으로 보인다 — 6.59에서 GIL 직렬 구간 ~1개를 빼면). SMT가 만든 하드웨어 스레드 수(16)를
그대로 "쓸 수 있는 병렬성의 크기"로 읽으면 과대평가된다는 뜻이다.

## 4. #589에 대한 답

- **"N=3이 최적이다"는 이 박스(16 vCPU/SMT 켬)에 매인 값이다 — 일반화 안 된다.** 같은 세대·같은
  물리 코어 수(8)라도 SMT를 끄면 최적 N은 **2로 줄어든다.**
- **원인(GIL, 프로세스 하나가 박스 전체를 못 씀)은 SMT 유무와 무관하게 재현된다.** 처방의
  방향(프로세스를 쪼갠다)은 안 바뀐다 — 바뀌는 건 "몇 개로 쪼개는가"라는 숫자뿐이다.
- **"1.04 vCPU GIL 바닥"이라는 원판의 숫자도 vCPU 회계 단위에 매인 값일 가능성이 크다.**
  이번 판은 GIL 프로브(F/Z/C 3팔)를 다시 걸지 않아 `rho`를 직접 재계산하지 못했다(원판도 §5에서
  "판정선 ㄹ은 이 설계로 못 쓴다"고 스스로 적어뒀다 — 그 한계가 그대로 이어진다). 물리 코어
  단위로 GIL 점유율을 다시 재려면 §8 grid(F/Z/C)를 SMT-off 박스에서 재현해야 한다 — **이번
  판의 범위 밖.**
