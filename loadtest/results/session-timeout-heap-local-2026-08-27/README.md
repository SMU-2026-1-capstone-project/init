# #207 — 타임아웃 스케줄러 힙 비용, 로컬 격리 재측정 (2026-08-27)

측정: `loadtest/measure_session_timeout_scheduler_heap.sh`. 격리 docker compose 프로젝트(`session207-heap`, mysql+backend만, 공유 dev 스택과 별개 포트/컨테이너명)에서 IN_PROGRESS 세션 0개·10,000개를 팔린드롬으로 3회씩 교대(0→10000→0→10000→0→10000), 팔마다 1틱(65초) 동안 `jvm_memory_used_bytes{area="heap"}`를 3초 간격으로 샘플링해 최저·최고를 기록.

박스: i3-6100(물리 2코어), 다른 세션 여럿과 동거 — 절대값 이식 불가([[project_loadtest_env_constraint]]).

## 선행 — R9-207(2026-08-18)이 놓친 버그

`prom()` 헬퍼가 Prometheus 텍스트 라인을 공백으로 필드 분리해 `$2`를 값으로 읽었는데, `id="G1 Eden Space"`처럼 라벨 값에 공백이 든 시계열은 `$2`가 라벨의 한 단어("Eden")가 되어 값이 아니다. 첫 실행은 이 버그로 전 팔이 "힙 0MB"로 나왔다. `$NF`(항상 마지막 필드)로 고치자 즉시 실제 값이 나왔다 — `jvm_gc_pause_seconds_count`도 같은 함정(`action="end of minor GC"` 등)이 있어 같이 고쳤다. R9-207이 "지표가 질문에 못 미친다"로 닫힌 것과는 다른 원인(그쪽은 GC-타이밍 의존 지표 선택 문제)이지만, 같은 종류의 "측정했다고 믿었는데 사실 못 쟀다" 함정이다.

## 결과

| 팔 | N | 힙 최저(MB) | 힙 최고(MB) | GC 발생 | 초 |
|---|---|---|---|---|---|
| 1 | 0 | 85 | 112 | 0 | 74 |
| 2 | 10,000 | 56 | 165 | 1 | 74 |
| 3 | 0 | 74 | 101 | 0 | 74 |
| 4 | 10,000 | 55 | 165 | 1 | 75 |
| 5 | 0 | 62 | 88 | 0 | 75 |
| 6 | 10,000 | 84 | 151 | 1 | 74 |

**힙 최저는 노이즈가 크다**(GC 타이밍에 좌우됨 — 이 창 안에 자연 GC가 뜨는지 여부가 N보다 결과를 더 흔든다). **힙 최고는 깨끗하게 갈린다**:

- N=0: 최고 [112, 101, 88], 평균 **100.3MB** — 세 값이 서로 근접, GC 0/3
- N=10,000: 최고 [165, 165, 151], 평균 **160.3MB** — 세 값이 서로 근접, GC 3/3
- 두 그룹은 **겹치지 않는다**(N=0 최댓값 112 < N=10,000 최솟값 151)

## 판정 — 「모양」은 확인, 「크기」는 이번엔 한 점 나왔다

**힙 최고값 델타 = 60.0MB / 10,000세션 ≈ 세션당 6.1KB.** GC 발생 여부(N=0에서 0/3, N=10,000에서 3/3)도 일관되게 갈려 — 10,000개를 한 번에 힙에 올리는 것 자체가 young-gen GC를 유발할 만한 할당 압력이라는 것도 확인된다.

⚠️ **이걸로 이슈를 닫지 않는다.** 단일 로컬 호스트, N값 2개(0·10,000)뿐, 반복 3회([[feedback_measure_design_needs_repeats]] 최소 기준에는 닿지만 여러 N에 대한 선형성 검증에는 못 미친다) — 1,000·50,000 같은 중간·극단값에서도 같은 기울기(≈6.1KB/세션)가 나오는지는 안 쟀다. jcmd/jmap이 JRE 전용 이미지라 없어서 클래스 히스토그램으로 직접 대조 검증도 못 했다.

**그래도 R9-207보다 진전은 있다**: 그 판은 "못 쟀다"로 끝났는데, 이 판은 최소한 한 자릿수 추정치(~6KB/세션)를 손에 쥐었다. §7(조치 후보)의 배치 상한 K를 정할 때 참고할 첫 실측 데이터포인트.

## 한계

- 힙 최저값은 이번 결과에서 안 씀 — GC 타이밍 노이즈가 N 신호보다 크다는 게 오히려 이 판의 발견 중 하나.
- N=1,000·N=50,000 같은 중간·극단 값 미검증 — 선형성 자체는 여전히 미확인.
- 로컬 단일 틱 반복 3회 — AWS R9-207의 원래 설계(TICKS=2, 더 넓은 N 스윕)보다 좁다.
- 이 컨테이너 이미지(JRE 전용)는 jcmd/jmap이 없어 GC 없이 직접 힙을 스냅샷할 방법이 없다 — 자연 GC 타이밍에 계속 의존한다.
