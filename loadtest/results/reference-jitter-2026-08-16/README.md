# 정답지 추출의 비결정성이 사용자 점수로 얼마가 되는가 (#234)

**답: 0.28점.** 정답지 내부 score 폭 **7.04** 가 사용자가 보는 `sync_rate` 로는 **0.28점**이 된다 — 약 25분의 1.

- 측정일: 2026-08-16
- rig: [`ai-server/scripts/measure_reference_jitter.py`](../../../ai-server/scripts/measure_reference_jitter.py)
- 선행: [#224](https://github.com/Shadowfit/init/issues/224) (추출이 결정적이지 않다 — 원인 규명 완료)

## 왜 쟀나

#224 가 «정답지 추출이 결정적이지 않다» 를 확정하고 폭을 **rep score 기준 ±1.3~3.3** 으로 적었다.
그런데 `score` 는 `_segment_reps` 가 rep 을 고를 때 쓰는 **내부 점수**이고 사용자가 보는 것은
`sync_rate` 다. 둘 사이에 DTW 가 있고 변환이 **지수**라(`100·exp(−d/30)`) «score ±1.3» 을
«점수 ±1.3» 으로 읽으면 안 된다.

이 숫자가 **«얼마나 심각한가» 를 정하는 유일한 값**이다 — [#232](https://github.com/Shadowfit/init/pull/232)
(정답지 고정) 정책의 강도가 여기서 나온다.

## 방법

```
① 같은 영상을 10회 추출        → 서로 다른 정답지 10벌
② 사용자 rep 하나를 고정        → 정답지로 뽑히지 않은 다른 rep
③ 10벌 각각으로 그 rep 을 채점  → sync_rate 10개
④ 그 분산이 답
```

- 영상: 1080×1920 · 25fps · 224프레임 (#224 와 **같은 영상**). 라이선스상 저장소에 두지 않는다
- 정답지: 매 판 «최고 점수 rep» — `V5`/`V4__seed_squat_reference.sql` 이 쓴 방법과 같다
- 사용자 입력: `rep_index=1 score=86.37 frames=24 min_knee=95.39` (첫 판에서 고정)

## 해석

### 가장 민감한 구간에서 쟀다

`100·exp(−d/30)` 은 거리가 클수록 기울기가 완만해진다. 관측된 Δd(0.0576)를 곡선의 각 지점에
놓으면:

| DTW 거리 | sync_rate | 같은 Δd 가 만드는 점수 변화 |
|---|---|---|
| **1.35 (이번 측정)** | 95.6 | **0.18점** |
| 10 | 71.7 | 0.14점 |
| 30 | 36.8 | 0.07점 |

즉 **정답지 흔들림의 피해는 자세가 좋은 사용자에게 가장 크다**(점수가 만점에 가까울수록 곡선이
가파르다). 이번 사용자가 `sync 95.6` — **그 가장 아픈 자리**였고, 그럼에도 0.28점이었다.

### 사용자 눈에는 거의 안 보인다

리포트의 `avgSyncRate` 는 정수로 나간다(E1 통주행 실측: `94`). 95.51 과 95.79 는 **둘 다 96 으로
반올림**된다. 정답지를 다시 뽑아도 화면 숫자는 대개 그대로이고, 반올림 경계에 걸릴 때만 1점
차이가 보인다.

## 🔴 미검증 / 한계

- **영상 1개 · 사용자 rep 1개 · 10판.** 다른 영상에서도 같은 비율인지는
  [#233](https://github.com/Shadowfit/init/issues/233) 의 질문이고, 그건 **다른 영상이 더 필요하다**
- 위 표는 «Δd 가 모든 사용자에게 같다» 를 가정한 계산이다. 사용자 동작이 다르면 정답지 흔들림과
  부딪히는 방식도 달라져 **Δd 자체가 커질 수 있다** — 안 쟀다. 그래서 «0.28점이 상한» 이라고
  단정하지 않는다
- DTW 거리는 **각도 값 차이와 시퀀스 길이 차이를 같이 탄다.** 이 실험은 둘을 가르지 않았다 —
  사용자가 실제로 받는 점수의 폭이 궁금한 것이라 섞인 채로 재는 것이 맞다고 봤다
- 정답지 프레임 수가 이번엔 36~37 로만 흔들렸다. #224 가 관측한 35~37 중 **35 는 안 나왔다**

## 곁가지 — #224 가 적은 폭보다 넓게 나왔다

#224 는 score 폭을 «±1.3~3.3» 으로 적었는데 10판에서는 **폭 7.04** 였다. 판을 늘리면 더 넓어질 수
있다는 뜻이다. **결론 방향은 안 바뀐다** — 더 넓은 입력 폭에서도 사용자 점수는 0.28점이었으므로
«전파가 작다» 가 오히려 단단해진다.


쓰기 때문이다. 저장소의 `demo_videos/demo_squat.mp4` 는 못 쓴다(#196 원인 ①).
