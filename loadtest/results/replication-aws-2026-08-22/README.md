### 1-1. 계측 바닥 — 이 라운드가 처음 실측했다

`lag_net = lag_rep − lag_src`. 자의 굵기를 게이트에서 **세 번** 쟀다(인위 5초 주입):

| 판 | 무대 | `lag_net p50` | 굵기 |
|---|---|---|---|
| 스모크 1 | 10만 행 | 6,018,106µs | +1.018초 |
| 스모크 2 | 10만 행 | 6,017,752µs | +1.018초 |
| **본 라운드 게이트** | **1,000만 행** | **6,017,416µs** | **+1.017초** |

🟢 **무대가 100배 커져도 굵기가 안 변한다.** 계측 바닥이 무대 크기와 무관하다는 뜻이고,
그래서 Q1 의 값은 **「~1초 이상만 신뢰」** 라는 단서를 근거 있게 달 수 있다.

> 📌 08-17 로컬 라운드는 이 굵기를 몰라서 Q3 을 통째로 잃었다(정확한 5초를 7~11.5초로 찍었다).
> 그 라운드가 못 닫은 것이 «현상» 이 아니라 «계측» 이었음을 이 표가 사후 확인한다.

## 4. 관측(측정 아님) — 리플리카를 새로 세우면 합류까지 얼마인가

설계 §4 가 측정에서 **제외**한 구간인데, 「운영이 자주 묻는 값」이라 기록만 한다(§9-1 🔶②).

| 무대 | 초기화(사본·전송·붓기·기동) | 따라잡기 |
|---|---:|---:|
| 10만 행 | 21초 | 0초 |
| **1,000만 행** | **61초** | **1초** |

🔴 **100배인데 3배다.** 물리 사본이라 데이터 크기에 선형으로 안 붙는다 — 파일 복사·전송이
지배하고 그건 순차 IO 다. 논리 덤프였으면 자릿수가 달랐을 자리다.
⚠️ 두 값 다 **gp3 · 같은 AZ** 조건이다.

## 5. 🔴 이 라운드는 `main` 이 아닌 커밋으로 돌았다

커밋 **`e2fbe6c`** — `main`(`df6db55`)에 **G2 결함 수정 하나**를 얹은 브랜치다.

스모크 1회차가 G2 에서 막혔고, 원인이 rig 에 있었다:

```
리플리카> INSTALL PLUGIN rpl_semi_sync_replica SONAME 'semisync_replica.so';
ERROR 1290 (HY000): The MySQL server is running with the --super-read-only option
```

`harden_replica` 가 건 `super_read_only=ON` 이 `INSTALL PLUGIN`(= `mysql.plugin` 쓰기)을 막았다.
리플리카 쪽 플러그인이 안 깔리니 소스 status 도 ON 이 못 됐다. 수정은 [#380](https://github.com/Shadowfit/init/pull/380).

**이 라운드는 그 수정본으로 돌았다.** `#380` 이 머지되면 이 커밋의 내용이 `main` 에 들어간다.

### 5-1. 스모크가 값을 했다

이 결함은 **1,000만 행 시딩과 사본 뜨기를 마친 뒤에야** 만났을 자리다. 10만 행으로 먼저 밟은
덕에 그 시간을 안 버렸다. 설계 §10-2 ㉱(「스모크를 먼저 태운다」)가 값을 한 사례다.

## 6. 정직하게 비어 있는 것

- 🔴 **다른 AZ 는 안 쟀다.** Q2 는 **「같은 AZ」 조건에서만** 성립한다. 설계 §9-1 ② 가 이 선택을
  「Q2 의 답을 자릿수 단위로 바꾼다」고 적었으므로, **「반동기의 대가는 N」을 조건 없이 인용하면
  안 된다.** 다른 AZ 는 더 비쌀 것으로 **추정만** 된다
- 🔴 **앱 경로가 아니다.** 부하가 rig 내장 SQL writer 라 **4차 라운드의 649 RPS 와 같은 단위로
  비교할 수 없다.** Q2 가 묻는 것이 «반동기가 커밋 경로에 무는 값» 이라 Spring 풀·GC 를 교란
  변수로 들이지 않으려고 고른 것이고, 그 대가가 이것이다
- **Q3(read-after-write)은 범위 밖이다.** 08-17 로컬 라운드가 「이 계측으로는 못 잰다」로 닫았다.
  다만 §1-1 이 자의 굵기를 실측했으므로 재도전의 출발점은 생겼다
- **G4(강등 관측)는 안 돌았다.** Q4 는 로컬 라운드가 이미 닫았고, 리플리카를 죽였다 살리는
  절차는 본 측정 앞에서 따라잡기를 새로 만든다
- **판마다 리플리카를 다시 세우지 않았다**(설계 §4 와 다른 지점). 대신 판마다 `rows_before` 를
  남겨 무대가 커지는 것을 표에서 보이게 했다
- **`ridealong/R1_worst_section.txt` 는 전부 0 이다.** 측정 박스엔 앱 트래픽이 없어
  `reports`·`exercise_sessions` 가 비어 있다. 「데이터가 없다」는 R1 이 물은 질문의 답이 아니다
  ([#371](https://github.com/Shadowfit/init/issues/371)). 🔴 **이 라운드 뒤에 R3 용 시딩을 따로 했으므로,
  나중에 그 테이블을 보고 「시딩했는데 왜 0이지」로 헷갈리지 말 것 — 순서가 그렇다**
- **합성 부하다.** 페이로드가 단일 템플릿 복제라 값 분포가 균일하다
